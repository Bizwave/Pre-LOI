## Goal
The operator's first commands. Chan can open a deal, record that it was paid (until Stripe in P15), bring a
buyer's files into the deal folder without ever overwriting one, see which deals are open and how long since
their package was complete, and back up the database and the deal files. Upgrading or downgrading the live
database makes a backup first (M11). Every file that comes in is hashed, classified by a keyword rules file,
inventoried page by page and recorded, so P5 and P7 can start from the database.

**Done when:** on a synthetic folder, `bw new-deal` then `bw intake` records 3 documents (a 3-page CIM, a
2-page P&L, a spreadsheet) and 5 pages, never overwrites a file, and moves a paid deal to `ready`; `bw status`
lists it; `bw backup` writes a database snapshot that opens with the deal in it; the whole suite passes on
Python 3.12 and 3.13.

## Risks and rollback
- A manual `bw` run in a Claude Code session would write into the live data folder (M5): every manual run
  here uses a scratch `BIZWAVE_DATA_DIR`; tests use temporary folders.
- An intake that overwrote a buyer's file would lose data and break traces: exclusive creation, versioned
  names and a test that the original bytes never change.
- A damaged or encrypted PDF: recorded, reported, exit 1; the run goes on.
- Starting the clock too early: only for a paid deal with a readable CIM; tests for each case.
- SQLite copied while open: the backup API only, never a file copy.
- Windows: reserved names refused; paths with spaces tested; `pip install -e .` again for the `bw` script.
- Rollback: revert the branch. No schema change; backups are new files only.
