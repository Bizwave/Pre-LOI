## Plain-language summary
P2 gives the Flash Review pipeline a memory. Today nothing records which deals exist, where they stand,
which files came in or which pipeline runs happened. P2 adds a small database (one file, in the data
folder outside the repository) with six tables for that: customers, deals, deal events (every status
change), documents, pages and pipeline runs. The structure is created and changed only through
migration scripts, so the same steps work on Chan's laptop now and on a hosted database later. A thin
set of functions ("the repository layer") is the only way the rest of the code writes to it, so rules
such as "a deal cannot jump from created to delivered" live in one place.

## What exists
- `config.settings().database_url`: default `sqlite:///<data folder>/bizwave.db` (P1). Nothing reads it yet.
- `config.ensure_data_dirs()`: creates the data folder; refuses a data folder or run log inside the
  repository. It does not check the database path (P1 review master-plan note; Chan's item 3a).
- `schemas.Deal.id` pattern: `^[a-z0-9][a-z0-9-]{2,40}$` (deal code names such as `acme-hvac`).
- `ingest.inventory(pdf) -> list[PageInfo(page, chars, has_text_layer, tables_found, images)]`: the
  `pages` table stores exactly these.
- Tech plan §4: relational tables for things queried or audited; JSON for whole documents; money in
  integer cents for commercial amounts; figures read from documents as exact decimals stored as text;
  Alembic with an upgrade → downgrade → upgrade test per migration; Postgres-compatible models.
- Packages: SQLAlchemy 2.1.8 and Alembic 1.20.1 are current. The MVP pins SQLAlchemy 2.0.37; this repo
  has its own environment, so `sqlalchemy>=2.0,<2.2` is safe.

## Findings from probes (scratch environment)
1. **SQLite drops time zones.** A `DateTime(timezone=True)` column returns a naive datetime. A small type
   that requires aware datetimes, stores UTC and returns aware UTC is needed, or SLA arithmetic will mix
   naive and aware times.
2. **SQLite does not enforce foreign keys by default** (`PRAGMA foreign_keys` = 0) and uses the `delete`
   journal. Both pragmas must be set on every new connection (an engine "connect" event).
3. **Enum CHECK constraints work on SQLite** when declared with `native_enum=False, create_constraint=True`
   (an invalid status raised IntegrityError), and compile cleanly for Postgres.
4. **Postgres compatibility can be tested without Postgres**: `CreateTable(table).compile(dialect=postgresql.dialect())`
   needs no driver.
5. **Alembic accepts a package path** (`script_location = "bizwave_preloi.db:migrations"`), so migrations
   ship inside the package and `upgrade()` works from any folder, including an installed copy.
6. **The MVP's migration pain** (its CLAUDE.md: autogenerate emits 50–260 lines of index-rename noise)
   comes from having no naming convention. Setting a `MetaData(naming_convention=...)` from the first
   migration avoids it, and SQLite needs `render_as_batch=True` for later column changes.
7. The MVP's `env.py` normalizes Windows SQLite paths with backslashes; P1's `as_posix()` URL avoids that.

## Gaps and risks
- **Database inside the repository** (item 3a): a `.env` line `BIZWAVE_DATABASE_URL=sqlite:///bizwave.db`
  would create the client database in the repo folder (git-ignored, but readable by Claude Code). Needs
  Chan's answer; reuse `config._inside`.
- **Decimal stored as text** cannot be summed or compared numerically inside SQL. Fine here (sums happen in
  Python), but worth a line in CLAUDE.md §8.
- **Status flow**: tech plan §4.3 has `created → awaiting_payment`. Design-partner pilots may be invoiced
  or free; a direct `created → awaiting_documents` path is probably needed (question for Chan).
- **Movable data folder**: documents should store paths relative to the deal folder, so moving
  `BIZWAVE_DATA_DIR` does not break records.
- **Gate must not pin growing state** (W1 lesson): later packets add tables, so P2's gate should assert
  "these six tables exist", not "exactly six tables".
- **Windows**: the SQLite file path is first exercised on Chan's machine; WAL creates `-wal` and `-shm`
  files next to the database (another reason to keep it out of sync folders).
