## What the master plan asks of P3
- Tech plan §9: "**P3 CLI skeleton:** `bw new-deal`, `bw intake`, `bw status`, `bw backup`", 1.5 hours,
  done when "intake of a synthetic folder records documents and pages".
- Tech plan §6.1:
  - `bw new-deal --customer EMAIL --tier flash`: creates the customer (if new) and the deal; prints the
    code name.
  - `bw intake DEAL --from FOLDER`: copies files into the data folder, hashes them, runs the inventory,
    records documents and pages; **reads the intake form answers (JSON or CSV export)**; marks `ready` and
    starts the SLA clock **when payment and package are complete**.
  - `bw status`: open deals, status, **SLA time left**.
  - `bw backup`: SQLite backup plus data folder copy.
- Stack (M6): Typer for the CLI (`typer` is not installed yet; current release 0.28.0).
- Layout target (§11): `cli.py` (the `bw` command), `ops/intake.py`, `ops/backup.py`.

## Gaps and conflicts found
1. **The intake form does not exist yet.** The tech plan names its fields (§6.3: asking price, proposed
   price, buyer cash, seller-note ideas, lender and quoted rate, working capital, offer deadline, industry,
   consent to AI-assisted processing) but not its tool or export format (D11, the upload tool, is open until
   Day 8). Parsing "JSON or CSV export" now means guessing a format. P4 ("structure from the intake form")
   reads most of the same fields.
2. **No place for AI consent.** The intake page asks for "consent to AI-assisted processing", but no table
   holds it, and nothing makes a deal without consent run in no-LLM mode. That is a master-plan gap: P7 will
   send pages to Claude for every deal unless something stops it.
3. **Payment has no record before P15.** "Marks ready when payment and package are complete" needs a
   payment, but payments arrive in P15 (Stripe). Today a deal can only leave `awaiting_payment` through a
   repository call.
4. **"SLA time left" needs the SLA rule** (D10, `rules/sla.yaml`, P15). P3 can show the time since the
   package was complete, not the time left.
5. **"Package complete" is not defined anywhere.** The flow starts the SLA clock at `ready`, so the rule
   matters: too loose and the clock starts before the CPA can work; too strict and deals sit.
6. **Document kinds.** `documents.kind` is `cim`, `recast`, `p_and_l`, `balance_sheet` or `other`. Nothing
   says how intake chooses. Keyword lists are "rules as data" (invariant 4), so they belong in a YAML file.
7. **Backup destination.** §3 says back up "into the synced folder" with SQLite's backup command; no setting
   names that folder. Copying the whole deals folder each night duplicates every PDF; copying only new or
   changed files is cheaper.
8. **Budget.** 1.5 hours does not cover four commands, file versioning, the inventory, backups, the
   automatic backup and their tests. A realistic estimate is about 3 hours, or about 2 hours if the intake
   answers move to P4 (where the structure is read anyway).

## Risks
- **Client data in a Claude Code session (M5).** `bw intake` and `bw backup` write into the data folder.
  In this environment every manual run must use a scratch `BIZWAVE_DATA_DIR`; tests already use temporary
  folders (conftest). The P2 proposal of a separate data folder for Claude Code sessions would make this
  automatic.
- **Overwriting a buyer's file** if intake copies over an existing name: data loss and a broken trace
  (invariant 1). Exclusive creation and versioned names avoid it.
- **A broken or encrypted PDF** stopping the whole intake. Better to record the file, report it, and exit
  non-zero so it is noticed.
- **Starting the SLA clock too early** (before payment, or with no CIM): the 24-hour promise would run while
  the deal cannot be worked.
- **Backups:** SQLite must be copied with its backup API, never as a file copy while open (WAL). A backup
  folder inside the repository would put client data next to the code: refuse it, like the data folder.
- **Windows:** reserved names; paths with spaces (OneDrive folders); `bw` installed as a console script
  needs `pip install -e .` again.
- **CLAUDE.md:** a `bw` line in §4 needs Chan's consent to the exact text.

## Recommendation in one paragraph
Build P3 as the operator's skeleton: `bw new-deal` (with a generated code name and a `--pilot` path that
skips payment), `bw paid` (a manual payment record until P15), `bw intake` (copy without ever overwriting,
hash, classify by a keyword rules file, inventory, record, and start the clock when a paid deal has a CIM),
`bw status` (open deals and time since the package was complete), and `bw backup` (SQLite backup API plus a
copy of new or changed deal files, into `BIZWAVE_BACKUP_DIR`), plus the automatic backup before upgrading or
downgrading the live database. Move the intake answers and the AI-consent record to P4, which reads the
form anyway, and add "AI consent required for Claude" to the master plan so P7 enforces it.
