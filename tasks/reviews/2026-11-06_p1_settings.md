**[blocker]** `src/bizwave_preloi/config.py:146` and `src/bizwave_preloi/ops/runlog.py:22`
- **What is wrong:** the inside-repo refusal checks only `data_dir`. It does not check `runlog_path`, and no test checks the run-log refusal at all.
- **Proof, part 1:** with `BIZWAVE_DATA_DIR` set to a temp folder and `BIZWAVE_RUNLOG=deals/runlog.jsonl`, run from the repo folder, `ensure_data_dirs()` accepts `runlog_path=/home/claude/pre-loi/deals/runlog.jsonl` without raising.
  - That value is exactly what the old `.env.example` shipped.
  - This packet starts loading `.env` automatically, so any `.env` copied from the old template now puts client model outputs inside the repo without warning.
  - A relative `BIZWAVE_RUNLOG=runlog.jsonl` would land at the repo root. That is outside the `Read(./deals/**)` deny rule, so Claude Code could read it.
- **Proof, part 2:** I replaced `RunLog`'s call to `ensure_data_dirs()` with plain `settings()` in memory and ran the suite. All 142 tests still pass, so removing the refusal goes unnoticed.
- **Why it matters:** the plan says the refusal also guards the run log (data contract lines 79–80 and the Reviewer Note). The "Done when" says the run log is written to the data folder. The amended invariant 8 (`CLAUDE.md:58-60`) says the run log lives outside the repository. As built, the refusal is incomplete and untested.
- **Fix:**
  - Make `ensure_data_dirs` also raise `DataFolderError` when `runlog_path` is inside `REPO_ROOT`.
  - Add tests that `RunLog()` raises (and creates nothing) when `BIZWAVE_DATA_DIR=REPO_ROOT/"deals"`, and when `BIZWAVE_RUNLOG` points inside the repo.
  - Adding these to the gate needs a `## Spec amendment` and Chan's OK.
  - P2 must apply the same check to a SQLite `database_url`.

**[should-fix]** `src/bizwave_preloi/config.py:136-139` (`_inside`) against `config.py:39-44` (`_find_repo_root`)
- **What is wrong:** `REPO_ROOT` is built with `.resolve()`, which follows symlinks, but `data_dir` only gets `abspath`, which doesn't.
- **Proof:** with a symlink to the repo in the scratchpad, `_inside(link/"deals", REPO_ROOT)` returns False, even though that path resolves to `/home/claude/pre-loi/deals`.
- **Why it matters:** the same gap appears whenever the repo is reached through a link: a symlinked code folder, a Windows junction, or macOS `/tmp` → `/private/tmp`. In those cases the refusal is skipped silently.
- **Fix:** compare `Path(x).resolve(strict=False)` on both sides, and add a symlink test (skip it where symlinks aren't allowed).

**[should-fix]** `.env.example:30-31`
- **What is wrong:** the comment "Set to 0 to ignore this file" can't work. The file is read before its own value takes effect.

- **Why it matters:** someone who sets 0 in the file believes the key is ignored. In fact Claude stays on, and client content can be sent to the API.
- **Fix:** remove the line from `.env.example`. State that the variable only works when set in the shell environment.
