### Findings

1. **[should-fix] src/bizwave_preloi/db/session.py:23-28 and db/migrate.py:31-35 — the next table-rebuilding migration will fail on a database that holds data, and leaves it half-migrated.**
   - **What is wrong:** migrations run on a connection where `PRAGMA foreign_keys=ON` has already been set, inside a transaction, so the migration cannot turn it off. A batch "recreate" on any parent table (deals, customers, documents, pipeline_runs) runs `DROP TABLE` while child rows exist.
   - **Proof:** I ran a trial 0002 that adds a deal status, against a database holding one deal and its events. It failed with `IntegrityError: FOREIGN KEY constraint failed`. pysqlite does not wrap DDL in a transaction, so `_alembic_tmp_deals` was left behind, and the retry then failed with `table _alembic_tmp_deals already exists`. The version stayed at 0001_core.
   - **Why it matters:** changing a status or constraint value is very likely within the sprint. The round-trip test cannot catch this because it runs on an empty database.
   - **Fix:** in `_run`, for SQLite:
     1. On a plain connection, run `PRAGMA foreign_keys=OFF` and commit.
     2. Run the migration inside `conn.begin()`.
     3. Run `PRAGMA foreign_key_check` and raise if it returns rows.
     4. Turn foreign keys back on.

     I confirmed this sequence works: the 0002 applied, the check came back empty and the rows were kept. Also make DDL transactional, using SQLAlchemy's pysqlite recipe (`isolation_level=None` plus `BEGIN` on the "begin" event), so a failed migration rolls back completely. Add a test: migrate a database that holds data through a recreate-style migration.

2. **[should-fix, needs Chan] src/bizwave_preloi/db/status.py:25 (and plan line 73) — `on_hold` forgets where the deal came from, so the flow can be bypassed.**
   - **Proof:** `awaiting_documents → on_hold → in_review → approved → delivered` succeeds, ending with `package_complete_at = None`. `awaiting_documents → on_hold → processing` also skips `ready`.
   - **Why it matters:** the SLA clock never starts. A deal can also reach delivery with no pipeline run. A later "no open footing failures" check could then pass with nothing to check, which bypasses invariant 7.
   - **Fix:** allow `on_hold` to return only to the status it came from (the last event's `from_status`), plus `cancelled`. Or refuse `processing`, `in_review` and `delivered` while `package_complete_at` is None. This changes the signed-off contract, so it needs a spec amendment and a gate change approved by Chan.

3. **[should-fix] src/bizwave_preloi/db/repo.py:110-116 — two document rows can point at one file.**
   - **Proof:** I added `inputs/cim.pdf`, overwrote the file with new content and added it again. Result: two rows, both with `stored_path = "inputs/cim.pdf"`. Row 1's sha256 no longer matches the file on disk.
   - **Why it matters:** a source reference (document, page) to row 1 now opens the wrong file (invariant 1).
   - **Fix:** refuse with a ValueError when the deal already has a document at that `stored_path` with a different sha256. Add `UniqueConstraint("deal_id", "stored_path")`; 0001 is not merged yet, so it can still change. Update the contract to match.

4. **[should-fix] repo.py:54-65, models.py:60, types.py:23-28 — inputs are not checked where they enter.**
   - **Cents:** `list_price_cents=750.5` is stored as SQLite REAL and read back as a float. `True` is stored as 1. This breaks "integer cents, never REAL".
   - **DecimalText:** it accepts `NaN`, `Infinity` and `sNaN`, none of which can be a figure. It also accepts values over 40 characters, which SQLite stores but Postgres VARCHAR(40) would refuse.
   - **Errors arrive late and in the wrong type:** a naive `at`, or a float price, fails only at flush, as `sqlalchemy.exc.StatementError`. That is not a ValueError subclass, so callers written to the contract ("naive → ValueError") will not catch it.
   - **Fix:**
     - Add a strict `Cents` type, or an `isinstance(v, int) and not bool` check, now; payments and credits will reuse it.
     - Make DecimalText refuse values that are not finite or are longer than 40 characters.
     - Check `at`, prices and an empty `by` inside the repo functions, so they raise ValueError/TypeError before anything is written, as `transition` already does for statuses.

5. **[should-fix] repo.py:32 and :57 — deal ids with a trailing newline are accepted.**
   - **Proof:** `DEAL_ID.match("acme-hvac\n")` passes, because `$` also matches before a final newline, and the id was stored as `'acme-hvac\n'`. `schemas.Deal` refuses the same id, so the comment "same as schemas.Deal.id" is wrong.
   - **Why it matters:** the deal folder name would contain a newline, which Windows cannot create.
   - **Fix:** use `DEAL_ID.fullmatch`, or end the pattern with `\Z`. Better, share one constant with `schemas`.

6. **[should-fix] repo.py:170-177 — `finish_run` overwrites a run that has already finished.**
   - **Proof:** a run finished as `failed` with an error, then finished again as `succeeded`. The second call was accepted and cleared the error.
   - **Why it matters:** the record of what happened in a run is silently lost.
   - **Fix:** refuse unless `run.status == "running"`.

7. **[should-fix] repo.py:155-158 — `llm_mode` reflects one use's switch, and "on" is never tested.**
   - **Proof:** with an API key set and only `BIZWAVE_LLM_DISABLED_USES=addbacks.classify_unmatched`, the run records `off`. The contract says "off" only in no-LLM mode or with no key.
   - **Fix:** use `s = settings(); "off" if s.no_llm or not s.has_api_key else "on"`. Add tests for "on" with a key and for "off" with no-LLM mode, in tests/test_db.py since the gate itself is frozen.

8. **[should-fix] db/migrations/versions/0001_core.py:7-10, migrations/env.py:8, models.py:19-25 — 0001 is not frozen.**
   - **What is wrong:** `op.create_table` takes its constraint names from the live `Base.metadata.naming_convention`, through env.py.
   - **Proof:** I edited the naming convention in the running process and ran the same 0001: the names changed (`uq_customers_email` became `uq_customers_email_v2`). The DDL parity test and `compare_metadata` both read the live models, so neither would notice.
   - **Why it matters:** fresh databases and existing ones would end up with different constraint names. Later `drop_constraint(name)` calls then fail on one of them. The docstring's claim of a "frozen copy" is untrue.
   - **Fix:** give every constraint in 0001 an explicit `name=`. Or add a test that pins `NAMING_CONVENTION` to its literal, with a comment that 0001 depends on it.

9. **[should-fix] .gitignore:36-39 — the safety net misses SQLite's companion files.**
   - **What is wrong:** `*.db`, `*.sqlite` and `*.sqlite3` are ignored, but `*.db-wal`, `*.db-shm` and `*.db-journal` are not (checked with `git check-ignore`).
   - **Why it matters:** P2 switches on WAL. If a database ever landed in the repository, the WAL file, which holds recent client writes, would show up for `git add -A`.
   - **Fix:** add `*.db-wal`, `*.db-shm`, `*.db-journal`, `*.sqlite-wal`, `*.sqlite-shm`.

### Master-plan notes
- **DDL parity test.** tests/test_db.py compares DDL text. The first batch-recreate migration stores `CREATE TABLE "deals"` (quoted), so the test will fail even when the schema is right. When that migration lands, switch to a normalized, structural comparison rather than deleting the test.
- **Creating the next revision.** There is no alembic.ini and no `revision` command, so `alembic revision --autogenerate` cannot be run as shipped. P3 or P4 needs a documented way, for example `python -m bizwave_preloi.db revision -m ...`.
- **Postgres.** `transition()` reads the status and then writes it. Under Postgres READ COMMITTED, two concurrent changes could overwrite each other; use `with_for_update()` when moving. SQLite WAL raises an error instead of losing the update.
- **Asking and proposed price.** These carry no record of where they came from (intake form or a CIM page), yet they will sit next to the maximum financeable price in the memo. P3 intake should record their source.
- **What later packets will see:**
  - DecimalText gives back the exponent as printed (`1E+3`), so P13 templates must format the number, not use `str()`.
  - UTCDateTime always returns UTC, so P15's SLA and memo dates must convert time zones explicitly.
  - `stages` JSON cannot hold a Decimal or a datetime; P7 should serialize stage results with `model_dump(mode="json")`.
- **Run provenance.** `git_sha` does not show uncommitted changes. Consider recording a "dirty" flag in P7.
- **Backups.** Until finding 1 is fixed, `bw backup` should run before every `upgrade` on the live database.
